<requirement name="build-and-test-contract" stories="architecture,build-executable,test-harness">
Implement in Go 1.22 or newer using only the standard library. The application root is a Go module, and its executable is the main package at `./cmd/dupfind`. Tests run under `go test`.
</requirement>
<requirement name="grader-contract" stories="conformance-grader">
`sources/run.sh` is the scoring entry point. It is supplied, not authored, and is staged verbatim into the application root. `drydock uat` runs `sh sources/run.sh` from the completed application root and takes its exit code and output as the score.
</requirement>
<requirement name="command-interface" stories="build-executable,command-options">
dupfind [--summary] [--min-size &lt;bytes&gt;] &lt;directory&gt;
</requirement>
<requirement name="walk-and-filter-files" stories="scan-and-group">
1. **Scope.** The tool walks &lt;directory&gt; recursively, including hidden files and directories (names beginning `.`). It considers regular files only. It neither follows nor reports symbolic links.
2. **Empty files are never duplicates.** A file of zero bytes is always ignored, which the default `--min-size 1` guarantees.
</requirement>
<requirement name="identify-duplicates" stories="scan-and-group">
3. **Duplicate test.** Files are grouped by size first. Only files that share a size are read. Within a size, files are grouped by the SHA-256 digest of their contents. A group of two or more files with the same size and digest is a duplicate group.
</requirement>
<requirement name="relative-paths" stories="scan-and-group,listing-csv">
4. **Paths** are written relative to &lt;directory&gt;, with `/` as the separator and no leading `./`.
</requirement>
<requirement name="ordered-results" stories="order-results">
5. **Order.** Groups are ordered by reclaimable bytes descending, then by digest ascending. A group's reclaimable bytes are `size × (files − 1)`. Groups are numbered from 1 in that order. Within a group, paths are ordered by byte value ascending.
</requirement>
<requirement name="unreadable-files" stories="scan-and-group">
6. **Unreadable files.** A file that cannot be read is skipped with one warning line on standard error. It does not change the exit code.
</requirement>
<requirement name="csv-output" stories="listing-csv,summary-csv">
Output is CSV on standard output: a header row, then data rows, with `\n` line endings. A field that contains a comma, a double quote, or a newline is quoted as RFC 4180 specifies. Go's `encoding/csv` writer produces this format.
</requirement>
<requirement name="listing-output" stories="listing-csv">
**Listing** (default): header `group,size,sha256,path`, then one row per file in every duplicate group. `sha256` is the lowercase hexadecimal digest. With no duplicates, only the header is written.
</requirement>
<requirement name="summary-output" stories="summary-csv">
**Summary** (`--summary`): header `groups,duplicate_files,reclaimable_bytes`, then one row. `duplicate_files` is the sum of `files − 1` over all groups. `reclaimable_bytes` is the sum of every group's reclaimable bytes. With no duplicates the row is `0,0,0`.
</requirement>
<requirement name="file-safety" stories="scan-and-group">
The tool reports each group of duplicates and the disk space that deleting all but one copy of each would recover. It never deletes, moves, or modifies a file.
</requirement>
<requirement name="minimum-size-filter" stories="command-options,scan-and-group">
`--min-size &lt;bytes&gt;` | Ignore files smaller than `&lt;bytes&gt;`. A positive integer; default `1`.
</requirement>
<requirement name="failure-behavior" stories="command-options">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="exit-codes" stories="command-options">
| `0` | Success, whether or not duplicates were found. |
| `1` | Operational failure: `&lt;directory&gt;` does not exist or is not a directory. |
| `2` | Usage error: missing or extra arguments, unknown option, `--min-size` not a positive integer. |
</requirement>
