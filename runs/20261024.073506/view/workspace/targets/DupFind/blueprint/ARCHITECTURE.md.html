ARCHITECTURE: DupFind

FieldValue
Version20261024 V1
DescriptionDefines the module structure and boundaries for the DupFind command-line application.
Provides./cmd/dupfind

Overview

DupFind is a read-only Go command-line application. The ./cmd/dupfind package starts the process and delegates command behavior to internal application packages. It uses the Go standard library and the module declared in go.mod.

Module Boundaries

ModuleResponsibilityOwns
cmd/dupfindProcess startup; invokes the CLI and exits with its returned status.main
internal/cliParses options and arguments, validates the directory, coordinates discovery and output, and routes diagnostics to stderr.CLI behavior
internal/discoveryWalks directories, identifies eligible regular files, hashes same-size candidates, and forms duplicate groups.Discovery and grouping
internal/outputOrders duplicate groups and encodes listing or summary CSV.CSV serialization

The CLI receives arguments and the stdout/stderr writers from main. Discovery returns data to the CLI; output consumes those groups and writes CSV. Application packages do not read the supplied grader or write to examined directories.

Module Ownership

BoundaryOwnerAllowed low-level access
PersistenceNoneDupFind has no persistent state or database.
Configurationinternal/cliCommand-line options only; no external configuration store.
File storeinternal/discoveryRead directory entries and candidate file contents through the Go standard library. Never write, move, or delete examined files.
External servicesNoneNo external services.

Technology Stack

TechnologyUse

go testProject test runner; bin/test.sh also runs go vet ./....

Guardrails

  • Build the executable as ./cmd/dupfind from the Go module root.
  • Use only the Go standard library; do not add third-party modules.
  • Keep the application read-only with respect to every examined directory.
  • Do not read or depend on sources/run.sh from application code.
  • Read file contents only when another eligible file has the same size.
