# ARCHITECTURE: DupFind

| Field       | Value |
|-------------|-------|
| Version     | 20261023 V1 |

| Provides    | Go module, cmd/dupfind entry point |
| Consumes    | — |

## Questions

- None.

## Purpose

DupFind is a standard-library Go command-line application that recursively scans a user-supplied directory and reports duplicate regular files.

## Module Structure

- `cmd/dupfind`: process entry point; parses process arguments, invokes application behavior, and calls `os.Exit`.
- `internal/cli`: command-line parsing, validation, and orchestration.
- `internal/discovery`: recursive traversal and eligible-file selection.
- `internal/grouping`: size filtering, SHA-256 hashing, and duplicate grouping.
- `internal/reporting`: deterministic CSV listing and summary output.
- `bin/test.sh`: POSIX local verification launcher.

## Boundaries

The application reads filesystem metadata and file contents only beneath the requested scan directory. It never writes, deletes, or moves files beneath that directory. Reporting writes only to standard output, while diagnostics are written to standard error.

The process entry point owns process exit status. Application behavior is exposed through testable functions that accept arguments and I/O streams.

## Technology Stack

- Go 1.22 or newer.
- Go standard library only.
- POSIX `sh` for the local test gate.

## Technical Decisions

- Files are grouped by size before contents are read.
- Candidate contents are hashed with SHA-256.
- CSV output uses `encoding/csv`.
- Diagnostics use concise conventional stderr lines; diagnostic wording is not part of the output contract.

| Consumes    | Go module and cmd/dupfind entry point |

## Questions

- None.

## Purpose

The command accepts `--summary`, `--min-size <bytes>`, and exactly one directory argument. The default minimum size is one byte.

## Command Contract

Valid forms are:

```text
dupfind [--summary] [--min-size <bytes>] <directory>
```

Options precede the directory. `--min-size` must be a positive integer. Unknown options, missing arguments, extra arguments, and invalid minimum sizes are usage errors with exit status 2, no standard output, and a diagnostic on standard error. The conventional Go help path is supported.

## Programmatic Acceptance

# FEATURE: File Discovery

| Field       | Value |
|-------------|-------|
| Version     | 20261023 V1 |
| Description | Defines recursive selection of eligible regular files beneath the scan directory. |
| Depends On  | FEATURE-DIRECTORY-VALIDATION.md |
| Provides    | recursive eligible-file discovery |
| Consumes    | scan-directory validation |

## Questions

- None.

## Purpose

DupFind recursively walks the validated directory, including hidden entries and directories. It considers regular files only and ignores symbolic links and zero-byte files.

## Discovery Rules

- Hidden files and directories are included.
- Regular files are eligible.
- Symbolic links are neither followed nor reported.
- Empty files are ignored.
- The examined tree is read-only from DupFind's perspective.

## Programmatic Acceptance

=== AC discovery-read-only ===
Intent: Scanning does not modify files in the examined directory.
import hashlib
import subprocess
import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as temp:
    root = Path(temp)
    first = root / "first"
    second = root / "second"
    first.write_bytes(b"same")
    second.write_bytes(b"same")
    before = {
        path.relative_to(root): hashlib.sha256(path.read_bytes()).digest()
        for path in root.rglob("*")
        if path.is_file() and not path.is_symlink()
    }

    result = subprocess.run(
        ["go", "run", "./cmd/dupfind", str(root)],
        capture_output=True,
        text=True,
    )
    assert result.returncode == 0
    after = {
        path.relative_to(root): hashlib.sha256(path.read_bytes()).digest()
        for path in root.rglob("*")
        if path.is_file() and not path.is_symlink()
    }
    assert result.returncode == 0
    assert after == before
=== END AC discovery-read-only ===

# FEATURE: File Hashing

| Field       | Value |
|-------------|-------|
| Version     | 20261023 V1 |
| Description | Defines candidate filtering and exact duplicate grouping by size and SHA-256 digest. |
| Depends On  | FEATURE-FILE-DISCOVERY.md |
| Provides    | duplicate candidate grouping |
| Consumes    | recursive eligible-file discovery |

## Questions

- None.

## Purpose

DupFind applies the positive minimum-size filter, groups candidates by file size before reading contents, and hashes only files sharing a size. Files with equal size but different contents remain separate. Unreadable files are skipped with one warning and do not change the successful exit status.

## Grouping Rules

For each eligible file at or above the minimum size, files are grouped by size. Contents are read only within a size group containing multiple candidates. SHA-256 digests then identify exact duplicate groups. A group is reportable only when it contains at least two files.

## Programmatic Acceptance
