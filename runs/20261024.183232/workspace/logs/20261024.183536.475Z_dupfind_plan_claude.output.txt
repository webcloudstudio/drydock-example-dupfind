# FEATURE: Target Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reject a missing or non-directory target with exit 1 and no standard output. |
| Depends On  | FEATURE-CommandLine.md |
| Provides    | cli.ValidateTarget |
| Consumes    | cli.Run |

## Questions

- None.

## Purpose

After argument parsing succeeds, the directory argument is validated. A nonexistent path or a regular file exits 1 with exactly one stderr line and empty stdout. Validation runs after usage validation, so usage errors keep exit 2.

## Behavior

- `cli.ValidateTarget` accepts a directory and returns a rejection for a nonexistent path or a regular file.
- A rejected target produces exit 1, one stderr line, and no stdout.
- Usage errors detected by `cli.Run` are reported before target validation runs.

# FEATURE: Pipeline

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Wire the cmd/dupfind main package to argument parsing, validation, scanning, grouping, ordering, and CSV rendering as the built executable. |
| Depends On  | FEATURE-CommandLine.md, FEATURE-TargetValidation.md, FEATURE-Walker.md, FEATURE-SizeFilter.md, FEATURE-Grouping.md, FEATURE-UnreadableFiles.md, FEATURE-ListingCSV.md, FEATURE-ListingOrder.md, FEATURE-ListingEmpty.md, FEATURE-Summary.md |
| Provides    | cmd/dupfind executable |
| Consumes    | cli.Run, cli.ValidateTarget, scan.Walk, scan.FilterSize, scan.Group, output.WriteListing, output.WriteSummary |

## Questions

- None.

## Purpose

This is the assembly story. `cmd/dupfind/main.go` calls `cli.Run` with an execute function. The execute function runs walk, size filter, group, order, and render in sequence, choosing listing or summary output. Only `main` calls `os.Exit`.

## Behavior

- Standard output carries only CSV: the listing by default, or the summary with `--summary`.
- Diagnostics go to standard error.
- Exit codes are 0 on success, 1 for an invalid target, and 2 for a usage error.

=== AC pipeline-read-only ===
Intent: The built executable leaves every file under the examined directory byte-identical after a run.
Requires: executable=go; scope=test

import os
import tempfile

from drydock_go import cli_runner


def snapshot(root):
    state = {}
    for dirpath, _, filenames in os.walk(root):
        for name in filenames:
            path = os.path.join(dirpath, name)
            with open(path, "rb") as f:
                state[os.path.relpath(path, root)] = f.read()
    return state


with tempfile.TemporaryDirectory() as tmp:
    for name in ("a", "b"):
        os.makedirs(os.path.join(tmp, name))
        with open(os.path.join(tmp, name, "same.bin"), "wb") as f:
            f.write(b"unchanged bytes")
    before = snapshot(tmp)
    code, out, err = cli_runner(tmp)
    print(code, out, err)
    assert code == 0, (code, out, err)
    after = snapshot(tmp)
    assert after == before, (before, after)
=== END AC pipeline-read-only ===

# FEATURE: Test Harness

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Ship the POSIX bin/test.sh launcher and gate the finished application on the supplied grader as the terminal story. |
| Depends On  | FEATURE-Walker.md, FEATURE-SizeFilter.md, FEATURE-Grouping.md, FEATURE-UnreadableFiles.md, FEATURE-ListingCSV.md, FEATURE-ListingOrder.md, FEATURE-ListingEmpty.md, FEATURE-Summary.md, FEATURE-CommandLine.md, FEATURE-TargetValidation.md, FEATURE-Pipeline.md |

## Questions

- None.

## Purpose

This is the terminal story. It depends on every implementation story. `bin/test.sh` is a POSIX sh launcher that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass. The supplied `sources/run.sh` is the full-suite acceptance gate.

## Behavior

- `bin/test.sh` is POSIX-compatible sh and runs from the application root.
- `bin/test.sh` exits zero only when `go vet ./...` and `go test ./...` both pass.
- The terminal acceptance runs `sh sources/run.sh` as the full suite and requires exit zero.
