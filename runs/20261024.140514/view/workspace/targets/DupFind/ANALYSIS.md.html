Planning Instructions

Delivery Shape

A standard-library Go command-line application takes options and a directory path, recursively scans regular files, groups exact duplicates, and writes either a CSV listing or summary to standard output. Diagnostics go to standard error; exit codes distinguish usage errors from operational failures. The required execution flow is build, parse and validate arguments, scan and group files, format results, then verify the complete supplied grader.

Test and Acceptance Strategy

Use focused tests with temporary directory trees for argument validation, traversal rules, grouping, ordering, CSV formatting, summaries, and exit codes. bin/test.sh runs vet and the automated tests. The terminal verification story runs the complete supplied grader and declares Suite: full; its acceptance is bounded to the harness result. Sea Trial st-001 records the same project-level full-grader proof.

Sequencing and Dependencies

Build the Go module and executable before exercising the command. Implement argument handling before scanning; scanning and grouping precede ordering and output formatting. The listing and summary depend on the same duplicate results. The automated test script runs vet and tests. The terminal verification story follows every implementation story and runs the staged grader from the application root.
