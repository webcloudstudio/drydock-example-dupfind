# FEATURE: Target Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Reject a missing or non-directory target argument with exit status 1 and no standard output. |
| Depends On  | ARCHITECTURE.md, FEATURE-CommandLine.md |
| Provides    | cli.ValidateTarget |
| Consumes    | cli.Run |

## Questions

- None.

## Purpose

After argument parsing succeeds, the directory argument is checked. A path that does not exist, or
that exists but is a regular file rather than a directory, is an operational failure: the process
writes exactly one diagnostic line to standard error, writes nothing to standard output, and exits
with status 1.

Validation runs after usage validation, so a usage error (exit 2) takes precedence over an invalid
target.

## Behavior

- Input: the single directory argument returned by `cli.Run` argument parsing.
- A nonexistent path: exit 1, one stderr line, empty stdout.
- A path that exists and is a regular file: exit 1, one stderr line, empty stdout.
- A path that is a directory: validation passes and control returns to the pipeline.
- Symbolic links that resolve to a directory are accepted as the target; the walker governs what is
  examined beneath it.

# FEATURE: Pipeline

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |
| Description | Wire the command-line entry point to walk, size filter, group, order, and render, producing the built `dupfind` executable. |
| Depends On  | ARCHITECTURE.md, FEATURE-Walker.md, FEATURE-SizeFilter.md, FEATURE-Grouping.md, FEATURE-UnreadableFiles.md, FEATURE-ListingCSV.md, FEATURE-ListingOrder.md, FEATURE-ListingEmpty.md, FEATURE-Summary.md, FEATURE-CommandLine.md, FEATURE-TargetValidation.md |
| Provides    | cmd/dupfind executable |
| Consumes    | cli.Run, cli.ValidateTarget, scan.Walk, scan.FilterSize, scan.Group, output.WriteListing, output.WriteSummary |

## Questions

- None.

## Purpose

This is the assembly feature. It owns `cmd/dupfind/main.go`, which passes an execute function to
`cli.Run`. The execute function runs the full pipeline in sequence:

1. walk the target directory (`scan.Walk`)
2. drop zero-byte and too-small files (`scan.FilterSize`)
3. group by size then SHA-256 (`scan.Group`), warning on unreadable files
4. order groups and paths (`output.Order`)
5. render either the listing (`output.WriteListing`) or the summary (`output.WriteSummary`),
   chosen by the `--summary` flag

Only `main` calls `os.Exit`, with the code returned by `cli.Run`.

## Behavior

- The built executable is `dupfind`, produced by `go build ./cmd/dupfind`.
- Listing and summary modes both derive from the same grouping result, so their totals agree.
- Diagnostics go to standard error; standard output carries only the CSV.

## Programmatic Acceptance

# FEATURE: Test Harness

| Field       | Value |
|-------------|-------|
| Version     | 20261024 V1 |

| Depends On  | ARCHITECTURE.md, FEATURE-Walker.md, FEATURE-SizeFilter.md, FEATURE-Grouping.md, FEATURE-UnreadableFiles.md, FEATURE-ListingCSV.md, FEATURE-ListingOrder.md, FEATURE-ListingEmpty.md, FEATURE-Summary.md, FEATURE-CommandLine.md, FEATURE-TargetValidation.md, FEATURE-Pipeline.md |
| Provides    | bin/test.sh |
| Consumes    | cli.Run, cmd/dupfind executable |

## Questions

- None.

## Purpose

Provide `bin/test.sh`, a POSIX-compatible script that runs `go vet ./...` and `go test ./...` from
the application root and exits zero only when both pass. This story is the terminal verification
gate: it depends on every implementation story, and its acceptance runs the supplied grader
`sh sources/run.sh` as the full suite, requiring exit zero.

## Behavior

- `bin/test.sh` is POSIX `sh`, not bash.
- It runs `go vet ./...` then `go test ./...` from the application root.
- It exits zero only when both succeed; any failure exits non-zero.
- The grader `sources/run.sh` is staged verbatim and is never modified, rewritten, or substituted.
