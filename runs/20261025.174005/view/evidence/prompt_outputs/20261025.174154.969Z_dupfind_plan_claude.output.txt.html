# ARCHITECTURE: DupFind

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Module layout, package boundaries, and pipeline of the dupfind command-line duplicate file finder. |
| Depends On  | None |
| Provides    | go.mod, internal/, cmd/dupfind, bin/ |

## Questions

- None.

## Overview

`dupfind` is a single-binary Go command-line tool. It finds regular files under a directory whose
contents are byte-for-byte identical, reports them as a CSV listing or a one-row CSV summary, and
never deletes, moves, or modifies any file.

Pipeline: parse arguments, validate the directory, walk, group by size, hash same-size groups with
SHA-256, order and number groups, emit CSV.

## Technology Stack

Derived from `TECHNOLOGY_STACK.md`; that file is the decision of record.

| Technology | Where it applies |
|---|---|
| Go 1.22 or newer, standard library only | All application code; `go.mod` declares no third-party requirement |
| go test and go vet | Test runner behind `bin/test.sh` |
| POSIX sh | `bin/test.sh` |

## Module Layout

| Path | Package | Responsibility |
|---|---|---|
| `go.mod` | module root | Module path and Go toolchain version; no `require` lines |
| `cmd/dupfind` | `main` | Calls `cli.Run(os.Args[1:], os.Stdout, os.Stderr)` and passes the result to `os.Exit`; the only caller of `os.Exit` |
| `internal/cli` | `cli` | `Run(args []string, stdout, stderr io.Writer) int`: argument parsing, directory validation, pipeline orchestration, exit codes |
| `internal/walk` | `walk` | Recursive directory walk yielding eligible regular files |
| `internal/dupes` | `dupes` | Size grouping, SHA-256 digest grouping, reclaimable bytes, ordering and numbering |
| `internal/report` | `report` | CSV listing and summary writers using `encoding/csv` |
| `bin/test.sh` | POSIX sh | Runs `go vet ./...` then `go test ./...` from the application root |

## Boundaries

- Only `main` calls `os.Exit`. `cli.Run` returns the exit code: 0 success, 1 operational failure, 2 usage error.
- Standard output carries only CSV. A failing command writes nothing to standard output and one diagnostic line to standard error.
- Warnings (unreadable file or subdirectory) go to standard error only and never change the exit code.
- File contents are read only by `dupes`, and only for files that share a size with another file.
- Files under the examined directory are opened read-only. Nothing is written, moved, or deleted there.
- Application code never reads `sources/run.sh` and never embeds a digest, path, or total.

## Module Ownership

| Boundary | Owning module | Allowed low-level APIs |
|---|---|---|
| Directory traversal and file metadata | `internal/walk` | `os.Lstat`, `os.ReadDir`, `io/fs` |
| File content reading and hashing | `internal/dupes` | `os.Open`, `crypto/sha256`, `io.Copy` |
| CSV output | `internal/report` | `encoding/csv` |
| Process arguments and exit codes | `internal/cli` and `cmd/dupfind` | `flag`, `os.Args`, `os.Exit` (main only) |
| Persistence, configuration files, external services | None; the tool has no persistent state | None |

## Foundation Scope

The foundation story creates `go.mod`, the package tree above, a `cmd/dupfind/main.go` that
delegates to `cli.Run`, and a minimal compiling placeholder in each internal package, so that
`go build ./cmd/dupfind`, `go vet ./...`, and `go test ./...` succeed before feature stories land.
The placeholder `Run` returns 0. `bin/` exists; `bin/test.sh` itself is delivered by the test-gate story.

# FEATURE: Arg Parsing

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Parse --summary, --min-size, and exactly one directory argument, rejecting malformed usage with exit 2. |
| Depends On  | ARCHITECTURE.md |
| Provides    | cli.Run, cli.Config |

## Questions

- None.

## Purpose

`cli.Run(args []string, stdout, stderr io.Writer) int` in `internal/cli` interprets the command
line `dupfind [--summary] [--min-size <bytes>] <directory>` and produces a parsed configuration for
later stories.

## Behavior

- Parsing uses a local `flag.FlagSet` with `flag.ContinueOnError` and its own output discarded.
- `cli.Config` carries `Summary bool`, `MinSize int64`, and `Dir string`. `MinSize` defaults to 1.
- Options precede the directory. Exactly one directory argument is required.
- Usage errors return exit code 2, write nothing to stdout, and write exactly one diagnostic line to stderr. Usage errors are:
  - no arguments, or an option with no directory;
  - more than one positional argument, or an option placed after the directory (it counts as an extra argument);
  - an unknown option, including `-h` and `--help`;
  - `--min-size` with a missing value, or a value that is not a positive decimal integer.
- A `--min-size` value is accepted only when it consists solely of ASCII decimal digits, is at least 1, and fits in an `int64`. Signs (`+5`, `-5`), zero, hexadecimal, exponent forms, and overflow are usage errors.
- Argument errors take precedence over directory validation.

## Reads

None.

## Writes

Standard error only, on usage errors.

# FEATURE: Directory Validation

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Exit 1 with empty standard output when the directory argument is missing or is not a directory. |
| Depends On  | ARCHITECTURE.md, FEATURE-ArgParsing.md |
| Provides    | cli.validateDirectory |
| Consumes    | cli.Config |

## Questions

- None.

## Purpose

After successful argument parsing, `cli.Run` checks that `Config.Dir` names an existing directory
before any walking or output.

## Behavior

- A nonexistent path, or a path that exists but is not a directory (for example a regular file), returns exit code 1.
- A failure writes nothing to stdout and exactly one diagnostic line to stderr.
- Validation runs after argument parsing and before the walk, so a usage error (exit 2) takes precedence over an operational failure (exit 1).
- An existing directory, empty or not, proceeds and the run succeeds with exit 0.
- The check uses `os.Stat`, so a symbolic link given as the directory argument that resolves to a directory is accepted.

## Reads

File metadata of the directory argument.

## Writes

Standard error only, on failure.

# FEATURE: Walk

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Walk the directory recursively and yield eligible regular files at or above the minimum size. |
| Depends On  | ARCHITECTURE.md, FEATURE-DirectoryValidation.md |
| Provides    | walk.Files |
| Consumes    | cli.Config |

## Questions

- None.

## Purpose

`internal/walk` enumerates the files that may be considered for duplicate detection. It never opens
file contents.

## Interface

```go
package walk

type Entry struct {
	Path string // relative to root, "/" separated, no leading "./"
	Size int64
}

func Files(root string, minSize int64, warn io.Writer) ([]Entry, error)
```

## Behavior

- Traversal is recursive and includes hidden files and directories (names beginning `.`).
- Only regular files are returned. Entries are classified without following links (`os.Lstat` or the `fs.DirEntry` type).
- Symbolic links are neither followed nor reported, whether they point at files or directories. A directory reachable only through a symbolic link is not traversed.
- Files whose size is below `minSize` are ignored. Zero-byte files are never returned, even if `minSize` is below 1.
- Paths use `/` as the separator and no leading `./`.
- A subdirectory that cannot be read yields one warning line on `warn`, is skipped, and the walk continues. This does not change the exit code.
- Return order is unspecified; ordering is the responsibility of later stories.

## Reads

Directory listings and file metadata under the root.

## Writes

Warning lines on the `warn` writer only.

GO_TEST = """package walk_test

import (
	"io"
	"os"
	"path/filepath"
	"sort"
	"testing"

	"MODPATH/internal/walk"
)

func build(t *testing.T, files map[string]string) string {
	root := t.TempDir()
	for name, body := range files {
		p := filepath.Join(root, filepath.FromSlash(name))
		if err := os.MkdirAll(filepath.Dir(p), 0o755); err != nil {
			t.Fatal(err)
		}
		if err := os.WriteFile(p, []byte(body), 0o644); err != nil {
			t.Fatal(err)
		}
	}
	return root
}

func check(t *testing.T, root string, files map[string]string, min int) {
	got, err := walk.Files(root, int64(min), io.Discard)
	if err != nil {
		t.Fatal(err)
	}
	var gotPaths []string
	for _, e := range got {
		gotPaths = append(gotPaths, e.Path)
		if int(e.Size) != len(files[e.Path]) {
			t.Errorf("size of %s = %d", e.Path, e.Size)
		}
	}
	var want []string
	for name, body := range files {
		if len(body) >= min && len(body) > 0 {
			want = append(want, name)
		}
	}
	sort.Strings(gotPaths)
	sort.Strings(want)
	if len(gotPaths) != len(want) {
		t.Fatalf("got %v want %v", gotPaths, want)
	}
	for i := range want {
		if gotPaths[i] != want[i] {
			t.Fatalf("got %v want %v", gotPaths, want)
		}
	}
}

func TestAcceptanceWalkEligibility(t *testing.T) {
