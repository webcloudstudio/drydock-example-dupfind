# FEATURE: Size Grouping

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Group candidate files by exact size and keep only sizes shared by two or more files, so unique-size files are never read. |
| Depends On  | FEATURE-Walk.md, ARCHITECTURE.md |
| Provides    | dupes.GroupBySize |
| Consumes    | walk.Files |

## Questions

- None.

## Purpose

Rule 3 of the build instructions says files are grouped by size first and only files that share a
size are read. This feature implements that first stage in `internal/dupes`.

## Interface

`dupes.GroupBySize` takes the eligible files produced by `walk.Files` (relative path and size) and
returns size buckets. Only buckets with two or more files are returned. The size is taken from the
walk result; file contents are never opened in this stage. A file whose size is unique appears in
no bucket and is therefore never opened for hashing.

## Reads and Writes

- Reads: the in-memory walk result only.
- Writes: nothing.

## Required Project Tests

The project test suite in `internal/dupes` contains `TestGroupBySizeOmitsUniqueSizes` (a unique
size produces no bucket) and `TestGroupBySizeKeepsSharedSizes` (two or more files with one size
produce one bucket holding all of them).

# FEATURE: Digest Grouping

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Hash same-size files with SHA-256 and form duplicate groups, skipping unreadable files with a stderr warning. |
| Depends On  | FEATURE-SizeGrouping.md, ARCHITECTURE.md |
| Provides    | dupes.GroupByDigest |
| Consumes    | dupes.GroupBySize |

## Questions

- None.

## Purpose

Rule 3 groups same-size files by the SHA-256 digest of their contents; a group of two or more files
with the same size and digest is a duplicate group. Rule 6 skips unreadable files with one warning.

## Interface

`dupes.GroupByDigest` takes the size buckets from `dupes.GroupBySize`. For each bucket it opens each
file read-only and streams it through `crypto/sha256`. The digest is the lowercase hexadecimal
encoding of the full contents. Files with identical size and digest form one group; groups with a
single member are dropped.

A file that cannot be opened or read yields exactly one warning line on standard error, is excluded
from grouping, and does not change the exit code. Files are opened read-only; nothing is written,
moved, or deleted under the examined directory.

## Reads and Writes

- Reads: the contents of files in shared-size buckets.
- Writes: warning lines to standard error only.

## Required Project Tests

`internal/dupes` contains `TestGroupByDigest` (identical contents group, same-size different
contents do not) and `TestGroupByDigestSkipsUnreadable` (an unreadable file is skipped with one
warning and does not fail the call).

import os

from drydock_go import cli_runner

def write(root, rel, data):
    p = os.path.join(root, rel)
    os.makedirs(os.path.dirname(p), exist_ok=True)
    with open(p, "wb") as f:
        f.write(data)

def snapshot(root):
    snap = {}
    for dirpath, dirnames, filenames in os.walk(root):
        for n in filenames:
            p = os.path.join(dirpath, n)
            with open(p, "rb") as f:
                snap[os.path.relpath(p, root)] = f.read()
        for n in dirnames:
            snap[os.path.relpath(os.path.join(dirpath, n), root) + "/"] = None
    return snap

content = b"keep me\n"

    write(root, "b/f2", content)
    write(root, "c/other", b"different!")

    code, out, err = cli_runner(root)
    print(out)
    print(err)
    assert code == 0
    code, out, err = cli_runner("--summary", root)
    assert code == 0
    assert snapshot(root) == before

# FEATURE: Group Ordering

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Compute reclaimable bytes per group, order and number the groups, and order paths within each group. |
| Depends On  | FEATURE-DigestGrouping.md, ARCHITECTURE.md |
| Provides    | dupes.Order |
| Consumes    | dupes.GroupByDigest |

## Questions

- None.

## Purpose

Rules 4 and 5 fix how paths are written and how groups and paths are ordered so output is
deterministic.

## Interface

`dupes.Order` takes the duplicate groups and returns them ordered and numbered.

- Reclaimable bytes of a group are `size x (files - 1)`.
- Groups are ordered by reclaimable bytes descending, then by digest ascending, and numbered from 1
  in that order.
- Within a group, paths are ordered by byte value ascending (plain string comparison).
- Paths are relative to the examined directory, use `/` as the separator, and carry no leading `./`.

## Reads and Writes

- Reads: the in-memory groups.
- Writes: nothing.

## Required Project Tests

`internal/dupes` contains `TestOrder` covering reclaimable-first ordering, digest tie-breaking,
and byte-order paths.

## Programmatic Acceptance

import csv
import hashlib
import os
import tempfile
from drydock_go import cli_runner

def write(root, rel, data):
    p = os.path.join(root, rel)
    os.makedirs(os.path.dirname(p), exist_ok=True)
    with open(p, "wb") as f:
        f.write(data)

fixtures = {
    b"0123456789": ["big/a", "big/b"],
    b"xyz": ["s/1", "s/2", "s/3", "s/4", "s/5"],
    b"tie-aa": ["t1/a", "t1/b"],
    b"tie-bb": ["t2/a", "t2/b"],
    b"tie-cc": ["t3/a", "t3/b"],
}
groups = []
for content, paths in fixtures.items():
    groups.append((len(content) * (len(paths) - 1), hashlib.sha256(content).hexdigest(), len(content), sorted(paths)))
expected = sorted(groups, key=lambda g: (-g[0], g[1]))

    rows = list(csv.reader(out.splitlines()))[1:]
    seen = []
    for r in rows:

            seen.append((r[0], r[2], int(r[1]), []))

    assert [s[1] for s in seen] == [g[1] for g in expected]

# FEATURE: Listing

| Field       | Value |
|-------------|-------|
| Version     | 20261025 V1 |
| Description | Write the CSV duplicate listing with header group,size,sha256,path using encoding/csv and wire the default mode of cli.Run. |
| Depends On  | FEATURE-GroupOrdering.md, FEATURE-ModuleBuild.md, ARCHITECTURE.md |
| Provides    | report.WriteListing |
| Consumes    | dupes.Order |

## Questions

- None.

## Purpose

The default output of `dupfind <directory>` is a CSV listing of every file in every duplicate group.

## Interface

`report.WriteListing` writes to standard output through `encoding/csv` with `\n` line endings
(`UseCRLF` false). The header row is `group,size,sha256,path`. One row follows per file of every
ordered group: group number, size in bytes, lowercase hexadecimal SHA-256, relative path. With no
duplicates only the header is written. Fields containing a comma, a double quote, or a newline are
quoted as RFC 4180 specifies, by the csv writer.

The default (non-summary) mode of `cli.Run` runs the walk, size grouping, digest grouping, and
ordering with the configured `--min-size`, then this writer, and returns 0. `--min-size` excludes
files smaller than the given number of bytes.

## Reads and Writes

- Reads: ordered groups.
- Writes: CSV to standard output only.

## Programmatic Acceptance

## Purpose

With `--summary` the tool reports the totals of the listing that the same options would produce,
instead of the listing itself.

## Interface

`report.WriteSummary` writes, through `encoding/csv` with `\n` line endings, the header
`groups,duplicate_files,reclaimable_bytes` and one row:

grouping, and ordering as the listing, with the same `--min-size`, and returns 0.
