<requirement name="go-stdlib-only" stories="foundation">
Implement in Go 1.22 or newer using only the standard library.
</requirement>
<requirement name="executable-main-package" stories="foundation pipeline">
The application root is a Go module, and its executable is the main package at `./cmd/dupfind`.
</requirement>
<requirement name="walk-regular-files" stories="scan-walk">
The tool walks `<directory>` recursively, including hidden files and directories (names beginning `.`). It considers regular files only. It neither follows nor reports symbolic links.
</requirement>
<requirement name="skip-empty-files" stories="scan-size">
A file of zero bytes is always ignored, which the default `--min-size 1` guarantees.
</requirement>
<requirement name="min-size-filter" stories="cli-args scan-size">
Ignore files smaller than `<bytes>`. A positive integer; default `1`.
</requirement>
<requirement name="group-duplicates" stories="scan-group">
Files are grouped by size first. Only files that share a size are read. Within a size, files are grouped by the SHA-256 digest of their contents. A group of two or more files with the same size and digest is a duplicate group.
</requirement>
<requirement name="options-before-directory" stories="cli-args">
Options precede the directory. Exactly one directory is required.
</requirement>
<requirement name="select-summary-output" stories="cli-args summary">
Write the summary instead of the listing.
</requirement>
<requirement name="csv-output" stories="list-csv summary">
Output is CSV on standard output: a header row, then data rows, with `\n` line endings. A field that contains a comma, a double quote, or a newline is quoted as RFC 4180 specifies. Go's `encoding/csv` writer produces this format.
</requirement>
<requirement name="list-one-row-per-file" stories="list-csv">
**Listing** (default): header `group,size,sha256,path`, then one row per file in every duplicate group. `sha256` is the lowercase hexadecimal digest.
</requirement>
<requirement name="list-header-only-when-no-duplicates" stories="list-empty">
With no duplicates, only the header is written.
</requirement>
<requirement name="summary-totals" stories="summary">
**Summary** (`--summary`): header `groups,duplicate_files,reclaimable_bytes`, then one row. `duplicate_files` is the sum of `files − 1` over all groups. `reclaimable_bytes` is the sum of every group's reclaimable bytes. With no duplicates the row is `0,0,0`.
</requirement>
<requirement name="group-order" stories="list-order">
Groups are ordered by reclaimable bytes descending, then by digest ascending. A group's reclaimable bytes are `size × (files − 1)`. Groups are numbered from 1 in that order.
</requirement>
<requirement name="path-order" stories="list-order">
Within a group, paths are ordered by byte value ascending.
</requirement>
<requirement name="relative-paths" stories="list-order">
Paths are written relative to `<directory>`, with `/` as the separator and no leading `./`.
</requirement>
<requirement name="skip-unreadable" stories="scan-unreadable">
A file that cannot be read is skipped with one warning line on standard error. It does not change the exit code.
</requirement>
<requirement name="exit-code-zero" stories="pipeline">
`0` | Success, whether or not duplicates were found.
</requirement>
<requirement name="exit-code-one" stories="cli-targets">
`1` | Operational failure: `<directory>` does not exist or is not a directory.
</requirement>
<requirement name="exit-code-two" stories="cli-args">
`2` | Usage error: missing or extra arguments, unknown option, `--min-size` not a positive integer.
</requirement>
<requirement name="report-failure-on-stderr" stories="cli-args cli-targets">
A failing command writes nothing to standard output and one diagnostic line to standard error.
</requirement>
<requirement name="posix-test-gate" stories="test-harness">
The completed application provides a POSIX-compatible `bin/test.sh` that runs `go vet ./...` and `go test ./...` from the application root and exits zero only when both pass.
</requirement>
<requirement name="test-coverage" stories="test-harness">
The suite covers each rule, each output form, and each exit code against real temporary directories.
</requirement>
