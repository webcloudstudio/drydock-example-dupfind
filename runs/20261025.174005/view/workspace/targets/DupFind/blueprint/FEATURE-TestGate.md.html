FEATURE: Test Gate

FieldValue
Version20261025 V1
DescriptionProvide the POSIX bin/test.sh launcher and a Go test suite that covers every rule, output form, and exit code of dupfind against real temporary directories.
Depends OnFEATURE-ModuleBuild.md, FEATURE-DirectoryValidation.md, FEATURE-Listing.md, FEATURE-Summary.md
Providesbin/test.sh
Consumescli.Run

Purpose

The application needs one command that decides whether the code is healthy. bin/test.sh runs go vet ./... and then go test ./... from the application root and exits zero only when both pass. The Go test suite behind it exercises the finished tool, so a regression in any earlier story turns this gate red.

Trigger

A developer, the build engine, or the terminal verification story runs sh bin/test.sh.

Sequence

  1. bin/test.sh is POSIX sh: no bashisms, no arrays, no [[ ]].
  2. It derives the application root from the script's own location (dirname "$0"/..), changes

into it, so the result is the same from any working directory.

  1. It runs go vet ./.... A non-zero status stops the script with that non-zero status.
  2. It runs go test ./.... Its status becomes the script's exit status.
  3. The script exits 0 only when both commands succeeded.

Test Suite Coverage

The Go test suite lives in *_test.go files beside the packages under internal/. Tests call cli.Run(args, &stdout, &stderr) with bytes.Buffer writers over real directories made with t.TempDir(), and parse standard output with encoding/csv. Expectations are written against observed real output. Each rule has at least one test named for the behavior:

AreaBehavior covered
ScopeHidden files and hidden directories are walked; nested directories are walked
ScopeA symbolic link to a file is neither followed nor reported; a link to a directory is not traversed
Empty filesZero-byte files are never reported, including with an explicit small --min-size
Minimum sizeFiles below --min-size are ignored; the default is 1
Duplicate testSame size but different content is not a duplicate; same size and content is
Duplicate testFiles with a unique size are never opened for hashing
PathsRelative to the directory, / separator, no leading ./
OrderGroups by reclaimable bytes descending then digest ascending, numbered from 1; paths by byte value
UnreadableAn unreadable file is skipped, one warning on stderr, exit code unchanged (skipped when running as root)
ListingHeader group,size,sha256,path; header only when there are no duplicates
CSV quotingA path containing a comma is quoted and round-trips through encoding/csv
SummaryHeader groups,duplicate_files,reclaimable_bytes; 0,0,0 when there are no duplicates; totals equal those of the listing under the same options
Exit codes0 for success with or without duplicates; 1 for a missing directory or a regular file; 2 for no arguments, extra arguments, unknown option, --min-size of abc and of 0
Failure outputExit codes 1 and 2 write nothing to standard output

Reads

  • The application source tree, through go vet and go test.

Writes

  • Nothing outside temporary directories created by the tests themselves. The suite never writes

under any directory the tool examines other than the temporary fixture it created.

User Acceptance

  • None.

Guardrails

  • bin/test.sh is POSIX sh; it does not require bash.
  • The test suite never reads sources/run.sh and never embeds a digest, path, or total taken from it.
  • Tests write only inside temporary directories they create; nothing under a directory the tool examines is deleted, moved, or modified by the tool.
  • The tool is built with the standard library only; no third-party module is added for testing.
